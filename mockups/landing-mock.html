Safety Invariants

        
Architected for Trust and Zero Pollution

        
How Agentic QA Swarm eliminates manual black-box QA while safeguarding your environments.

      


      

        

          
🛡️

          
Platform Warm Sandbox

          

            Your application runs in an isolated, reusable namespace (aqs-test) with pre-deployed 
            PostgreSQL and Redis dependencies. Your staging and production environments are never accessed or targeted.
          

          Isolated Namespace · No Client Staging Target
        


        

          
👤

          
Human Confirmation Gate

          

            Zero auto-run. GitHub events only produce notifications in your inbox. No Kubernetes Jobs or pods are ever 
            created until an engineer explicitly approves the run with a verifiable identity token.
          

          POST /notifications/{id}/confirm · Fail-Closed
        


        

          
⚡

          
Inspectable k6 & Blocking Rehearsal

          

            The LLM agent generates standard, versionable k6 test scripts. A lightweight unit rehearsal 
            must return 2xx before authorizing a full concurrency swarm, preventing compute waste on broken builds.
          

          rehearsal.passed=true · Non-Proprietary Code
        


        

          
🔄

          
100% Verified Reset

          

            Between every run, the platform restarts services, wipes PostgreSQL tables, flushes Redis cache, and verifies 
            state via health probes (reset_verified=true). If verification fails, the warm sandbox enters quarantine.
          

          Zero Cross-Run Contamination · Rebuild Hygiene
        

      

    


    
    

      

        
Comparison

        
Why Agentic QA Swarm is Built Differently

        
A breakdown of our design invariants compared to brittle manual E2E setups and uncontrolled autonomous agents.

      


      

        

          
            

              Feature / Invariant
              Agentic QA Swarm
              Autonomous LLM Testers
              Traditional Staging E2E
            

          
          
            

              Execution Target
              ✓ Platform Warm Sandbox (aqs-test)
              ✗ Customer Staging / Prod (High Risk)
              — Fragile Shared Staging
            

            

              Autonomy & Triggers
              ✓ Human Confirmation Gate (Zero Auto-Run)
              ✗ Runaway Autonomous Loop
              — Scheduled or CI trigger
            

            

              Test Script Artifact
              ✓ Standard, inspectable k6 scripts
              ✗ Proprietary prompt logs / black box
              ✗ Handcrafted brittle scripts
            

            

              State Hygiene
              ✓ 100% Verified Reset (reset_verified=true)
              ✗ Database pollution & orphaned rows
              — Manual seed scripts / dirty state
            

            

              Pre-Flight Safety Gate
              ✓ Blocking Unit Rehearsal (rehearsal.passed)
              ✗ Blind full execution
              ✗ Immediate run (fails late)
            

            

              Bug Finding Capability
              ✓ Race conditions & business logic flaws
              — Superficial UI & text scraping
              — Only checks hardcoded assertions
            

            

              Runner Network Security
              ✓ Deny-by-default (Zero LLM egress in pods)
              ✗ Open internet egress for models
              — Full CI host privileges
