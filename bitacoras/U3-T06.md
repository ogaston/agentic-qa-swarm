### Defectos reales hallados por las propiedades (rojo, ejemplo reducido, arreglo, regresion fija)
Los tres fallaron al correr `pytest -k pbt` de este worktree ANTES del arreglo (salidas de esta ronda):

1. `test_pbt_evidence_truncation_*` — recorte supera el tope (agent-reporter/reporter.py `_truncate`):
   ```
   Falsifying example: ...(case=(1, 1, [b'01']))
   assert 28 <= 1  where 28 = len(b'\n[...recortado: 1 bytes...]\n')
   ```
   max_object_bytes=1, max_total_bytes=1: con tope menor que la marca, el objeto ocupaba la marca entera; con el presupuesto total agotado cada objeto restante aportaba ~28 bytes (790 > 700 en la regresion). Ademas el corte por bytes partia caracteres UTF-8 (U+FFFD de 3 bytes al re-codificar). Arreglo: si la marca no cabe solo se emite cabeza; cabeza y cola se ajustan a limites de caracter. Marca: ahora `N` es el exceso sobre el tope (aproximado en hasta 3 bytes cuando se ajusta a limite de caracter).
2. `test_pbt_redact_removes_seeded_secrets_*` — JSON serializado dentro de un campo de cadena (agent-reporter/redact.py):
   ```
   '{"msg": " {\\"Authorization\\": \\"Basic 00000000\\"} ", "n": 1}'  -> 00000000 sobrevive
   ```
   Las comillas escapadas (`\"`) no eran limite de clave ni de valor para `authorization`/`password`/`token`... Arreglo: `(?:\\?["'])?` en las claves y alternativa `bq` para valores `\"v\"`.
3. Misma propiedad — `{"msg": "\nBearer 00000000 "}` y JWT tras `\n`/`\t` escapados: la `n` del escape deja `\b`/el lookbehind sin limite y el secreto sobrevive. Arreglo: limite izquierdo `(?:(?<![A-Za-z0-9_])|(?<=\\[nrtbf]))` en bearer y JWT.
