### Cambio
- services/go-intake/internal/artifact/artifact.go (nuevo): `Resolver{Registry}.Resolve(Event) (Ref, error)` pura (solo errors, fmt, regexp, strings); `ErrUnresolvableArtifact`; registro por defecto ghcr.io, en minúsculas; repo en minúsculas solo en la imagen; PR de fork o sin repo de origen (comparación sin distinguir mayúsculas), tag latest/vacío/inválido, repo inválido, SHA no 40 hex minúsculas -> error. Registro inválido también -> error (fail-closed).
- services/go-intake/internal/artifact/artifact_test.go (nuevo): TestArtifactResolve (9 casos, cada ref validado contra contracts/events/notify.created.schema.json compilado) y TestArtifactRejections (13 casos + registro inválido).
- internal/intake/model.go: el puerto pasa a `Resolve(ctx, Classified)`; se elimina `StubResolver` y la constante ArtifactBuildFromRepo; se añade `ArtifactResolverFunc` y `NewArtifactResolver(registry)` (adaptador a internal/artifact).
- internal/intake/classify.go: `Classified` gana `Tag` (de refs/tags/* o release.tag_name) y `HeadRepo` (pull_request.head.repo.full_name). El mapa de github_event no cambia.
- internal/intake/handler.go: `errors.Is(err, artifact.ErrUnresolvableArtifact)` -> 422 `unresolvable_artifact`, sin persistir ni publicar; otros errores del resolvedor siguen siendo 503 `artifact_unavailable`.
- cmd/go-intake/main.go: usa `NewArtifactResolver(os.Getenv("ARTIFACT_REGISTRY"))`.
- internal/intake/handler_test.go: usa el resolvedor real; la clasificación comprueba kind/ref por tipo (incl. tag y release); prueba de PR de fork (422, sin persistir/publicar); TestWebhookResolverErrors (resolvedor que devuelve ErrUnresolvableArtifact -> 422; otro error -> 503; ninguno persiste ni publica); el caso "release con target_commitish no SHA" usa ahora un cuerpo en línea con rama.
- services/go-intake/testdata/github/release-published.json: `target_commitish` pasa de "main" a un SHA de 40 hex (b*40). Es el ajuste de fixture que anticipa C-75 y que CA-2 necesita (el criterio exige cuatro líneas, incluida la del release); no hay red para consultar el tag.
- Decisión sobre C-75: la tarea no define cómo obtener el SHA de un release real. Aquí solo se ajusta el fixture; en producción un release con `target_commitish` = nombre de rama sigue dando 400 `invalid_payload`. Queda como bloqueo/candidata (ver informe), no resuelto.
- 422 `unresolvable_artifact`: no está en el OpenAPI de U5 para /webhooks/github; NO se edita el contrato. Propuesto a C-11 (ya vinculado a C-46).
