### Nota de especificación (vacío detectado)
La tarea dice que el `FakeLLM` del planner "responde también a las superficies de `U3_FAKE_SURFACES_DIR`", pero no define el formato de esas entradas (qué plan responder para cada superficie/workflow). Tampoco define cómo el `FakeLLM` del reporter recibe respuestas para la evidencia sembrada (hoy `build_service` lo construye vacío y falla cerrado). Sin esas respuestas, CA-4 (`contrato-u2-plan-valido`, `reporte-valido`, `reporte-con-evidencia`) no puede pasar.
Decisión mínima tomada, sin cambiar contratos: fixtures JSON generadas por `u3-up.sh` en un directorio de estado fuera del worktree:
- planner: `U3_FAKE_SURFACES_DIR` contiene `*.json` con `{surface, workflow, plan}`; el planner registra `build_prompt(surface, workflow)` → `plan`.
- reporter: `REPORTER_FAKE_FIXTURES` apunta a un JSON con `[{run_id, evidence_uris, response}]`; el reporter registra `prepare(...).prompt` → `response`, leyendo la evidencia de `REPORTER_EVIDENCE_DIR`.
Esto queda marcado para revisión del orquestador.
