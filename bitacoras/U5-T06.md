## Decisiones no fijadas por la tarea
- Regla de default-deny (de conjunto): vive en `policy/default_deny.rego`, solo actúa con `--combine`, por lo que el CA-4 literal (sin `--combine`) no la ejerce. Se ejecuta aparte: `$K build deploy/flux/<env> | $C test --policy policy --all-namespaces --combine -` (CA-4b, 7/7 en dev y prod). Prueba negativa: quitando `default-deny` del build, falla con rc=1 ("falta NetworkPolicy default-deny").
- Verbos del Role `aqs-test-operator`: jobs, deployments, statefulsets, services, configmaps con get/list/watch/create/update/patch/delete; pods y pods/log con get/list/watch/delete (log solo lectura efectiva). Sin `secrets`, sin `pods/exec`.
- `go-warm-manager` y `go-reset` (aqs-system) reciben el RoleBinding por mandato de la tarea.
- allow-same-namespace usa `podSelector: {}` (solo mismo namespace); allow-from-control-plane usa `kubernetes.io/metadata.name: aqs-system`; allow-dns usa `kubernetes.io/metadata.name: kube-system` sin selector de pod.
- Reglas Rego: `package main`, `import rego.v1`; las reglas de ServiceAccount/ipBlock/Job/RoleBinding se acotan a namespace `aqs-test`; ipBlock revisa `to` y `from` en ingress y egress.

## BLOQUEO reportado (no abierto)
Los CronJobs `housekeeping` y `rebuild` (aqs-reset) usan el RBAC del API de Kubernetes (por el Role), pero `default-deny` bloquea el egress de aqs-test hacia el API server (fuera de aqs-test), y la tarea prohíbe ipBlock/egress externo. Probablemente fallarán en un clúster real al contactar el API. Tampoco hay egress hacia aqs-system ni MinIO. No se abrió nada; requiere decisión (p. ej. tarea candidata de egress al API server para aqs-reset, o mover la lógica al control plane).
