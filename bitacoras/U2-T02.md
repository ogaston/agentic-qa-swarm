Una corrida con `FailReason` terminaba en `done` tras el reset. Corrección: en `resetting`, con `FailReason` el destino es `failed`. Mismo comando después: `ok ... runctl`.

Segundo hallazgo (de `up`): arrancando el controlador antes que governance, la corrida quedaba detenida para siempre. Cambio: si el gate está **caído** (error/timeout) la salida segura se reintenta en cada paso (sin avanzar nunca); si el gate **deniega** la salida, la corrida queda `halted` con handoff y no se reintenta. Pruebas `TestGateErrorDownStopsRun` y `TestGateDeniesExitHaltsRunWithHandoff`.

### Cambio
- `runctl/` (dominio: estados/legalidad, puertos, controlador, fakes), `adapters/` (gate HTTP, diario JSONL con hash encadenado, fuente de eventos, outbox UUIDv5), `internal/obs` (copia del contrato de ui-api + métricas), `internal/httpapi` (`GET /runs/{id}`, verificador de identidad), `cmd/go-run-controller`, `Dockerfile`, `.dockerignore`, `go.mod/go.sum`.
- Decisiones: `confirmed=true` solo si la corrida trae `confirmed_by`; `workflow_allowed=true` solo si trae `flows` (si no, `unknown`); `reset_verified` se consulta al `WarmStateReader` para `warm_ready`/`deploying`, `ensayo_passed` viene de `rehearsal.*`; el controlador espera `rehearsal.passed` sin llamar al gate; `rehearsal.failed` cuenta como fallo de la fase `rehearse`. Sin `RUN_PHASES=fake` el servicio no arranca (no hay adaptadores reales de fase hasta T03-T06). Fakes de warm/fase en `main` son los de `runctl`.
- CA-4: no hay `ajv`/`yq` en la máquina; la validación contra `components.schemas.Run` se hace en `TestRunViewValidatesAgainstOpenAPISchema` (yaml.v3 + jsonschema/v6 extraen y validan el esquema real).

### Función `up` (usa `IDENTITY_USERS_FILE`, `GOVERNANCE_DATA_DIR`, `GOVERNANCE_AUTH=identity`, `GOVERNANCE_SERVICE_TOKEN`)
```bash
up() { t=$(mktemp -d)
  (cd services/go-identity && go build -o "$t/go-identity" ./cmd/go-identity) && (cd services/go-governance && go build -o "$t/go-governance" ./cmd/go-governance) && (cd services/go-run-controller && go build -o "$t/rc" ./cmd/go-run-controller) || return 1
  h=$(printf 'Cl4ve-de-Prueba-1!' | "$t/go-identity" hash-password)
  jq -n --arg h "$h" '[{username:"marta",password_hash:$h,role:"user"}]' > "$t/users.json"
  IDENTITY_USERS_FILE="$t/users.json" LISTEN_ADDR=127.0.0.1:18200 "$t/go-identity" > "$t/id.log" 2>&1 & idpid=$!
  gtok=$(head -c 24 /dev/urandom | base64 | tr -d '=+/')
  GOVERNANCE_DATA_DIR="$t/gov" GOVERNANCE_SERVICE_TOKEN="$gtok" GOVERNANCE_AUTH=identity IDENTITY_URL=http://127.0.0.1:18200 LISTEN_ADDR=127.0.0.1:18300 "$t/go-governance" > "$t/gov.log" 2>&1 & govpid=$!
  for i in $(seq 40); do curl -sf http://127.0.0.1:18300/readyz >/dev/null && break; sleep 0.25; done
  jq -c . contracts/events/examples/valid/run.confirmed.json > "$t/events.jsonl"
  RUN_PHASES=fake RUN_ALLOW_FAKE_PHASES=true RUN_DATA_DIR="$t/rcdata" RUN_EVENTS_FILE="$t/events.jsonl" RUN_OUTBOX_FILE="$t/out.jsonl" GOVERNANCE_URL=http://127.0.0.1:18300 GOVERNANCE_SERVICE_TOKEN="$gtok" IDENTITY_URL=http://127.0.0.1:18200 LISTEN_ADDR=127.0.0.1:18301 "$t/rc" > "$t/rc.log" 2>&1 & rcpid=$!; sleep 2
  tok=$(curl -s -X POST http://127.0.0.1:18200/auth/login -H 'Content-Type: application/json' -d '{"username":"marta","password":"Cl4ve-de-Prueba-1!"}' | jq -r .token); }
down() { kill $rcpid $govpid $idpid 2>/dev/null; rm -rf "$t"; }
```
(`$t/rc` es el binario, el diario va en `$t/rcdata`; la tarea pide `$idpid` y `$t`, y `$govpid`/`$rcpid` se añaden.)
